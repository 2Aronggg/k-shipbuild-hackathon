# WeldScan AI — 관리자용 판정 관제 대시보드

용접부 방사선투과검사(RT)에서 **검사자들의 판정 눈금이 얼마나 벌어져 있는지** 보는 품질관리 화면.

결함을 찾아주는 화면이 아님. 합격·불합격은 선급 규정표가 기계적으로 정하므로 사람 의견이 개입할 자리가 없고, 그 고정된 기준 위에 실제 판정을 겹치면 조직의 판정 산포가 직접 드러남. 이 대시보드가 측정하는 대상은 불량률이 아니라 **판정 일관성**임.

> 기획안 대비 변경된 설계 판단은 [`docs/design-decisions.md`](docs/design-decisions.md) 참조.

## 빠른 시작

### Streamlit — 로그인 · 역할 분기 포함 (권장)

```bash
pip install -r requirements.txt
streamlit run app.py
```

로그인 후 역할을 고르면 해당 화면이 뜸.

| 데모 계정 | 비밀번호 | 접근 가능 화면 |
|---|---|---|
| `admin` | `weldscan` | 관리자 · 책임 검사원 · 검사자 |
| `senior` | `weldscan` | 책임 검사원 · 검사자 |
| `worker` | `weldscan` | 검사자 |

계정 정보는 `app.py` 상단 `ACCOUNTS`에 있음. 실제 도입 시 사내 인증(LDAP/SSO)으로 교체할 자리임.

### 단일 파일로 열기

```bash
open weldscan_dashboard.html              # 관리자
open worker_dashboard.html                # 검사자
open "worker_dashboard.html?role=senior"  # 책임 검사원
```

두 HTML 모두 자체 완결형이며 빌드·서버·외부 의존성이 없음. 데이터가 파일 안에 인라인되어 있음.

## 역할 3단계 · 화면 2개

```
① 검사자         RT 필름 판독, AI 결함 확인, 1차 판정        worker_dashboard.html
      ↓ 애매하면 이관
② 책임 검사원     이관된 건만 받아 최종 확정                 worker_dashboard.html (권한만 다름)
      ↓ 판정이 한 줄씩 쌓임
③ 관리자         판정 안 함. 규정대로 했는지 채점            weldscan_dashboard.html
```

검사자와 책임 검사원은 **같은 판독 화면**을 씀. 책임 검사원으로 로그인하면 상단에 **이관 대기 목록**이 붙고, 카드를 고르면 그 건이 판독 화면에 로드됨. 버튼도 `이관 / 저장` → `반려 / 최종 확정`으로 바뀜.

두 화면을 잇는 계약은 저장 시 기록되는 **JSON 한 줄**이고, 검사자 화면 하단에 실시간으로 표시됨. `t`(모재두께) · `maxd`(긴지름) · `regions` · `report` 네 개가 필수 항목임.

> 검사자 화면은 구조 확인용 자리표시자임. Figma Make로 만드는 실제 판독 화면이 완성되면 `worker_dashboard.html`만 교체하면 됨.

## 핵심 개념 — 규정 마진

화면의 거의 모든 숫자가 이 값 하나 위에 서 있음.

```
마진 = 허용 한계 대비 실제 결함 크기        1.0 이 합격선

제1종 (기공)        max(결함점수합 / 점수상한,  최대결함크기 / 크기상한)
제2종 (슬래그·융합)  합계길이 / 길이상한
제3종 (균열)        크기 무관 전건 불합격
```

상한은 **모재두께**가 정함. 두께 20 mm 판에서 허용 지름이 5.0 mm인데 6.0 mm 기공이 나오면 마진 1.2 — 불합격.

이 값에는 난수도 모델 확신도도 들어가지 않음. 두께와 결함 치수만으로 결정되므로 누가 계산해도 같은 숫자가 나옴.

## 관리자 화면 구성

상단 필터(기간·부위·선종·연차)는 전 탭 공통. 화면 전체가 **RT 전용**임.

### 탭 1 — 운영 현황

| 구획 | 내용 |
|---|---|
| KPI 4종 | 판정 건수 · 규정 일치율 · 4급 판정 비율 · 에스컬레이션율 |
| 경보 4장 | 허용불가 결함 통과, 부위별 급락, 원본 입력 오탐, 관대 편향 |
| 01 정량 지표 3종 | 판독 시간 · 불일치율 · 보고서 작성, 기존 대비 목표선 |
| 90일 판정 필름 | 일별 규정 일치율 추이 |
| 02 부위 × 결함 불일치율 | 6부위 × 5결함 히트맵 |
| 03 에스컬레이션 대기 | 상급자 판단 대기 건, 기간 선택 바 (최근 1~4일) |

### 탭 2 — 모델·규정 품질

| 구획 | 내용 |
|---|---|
| 01 AI 모델 가용 범위 | 결함 4종 탐지 성능 · 판정 전제 조건 · 신뢰도 구간별 검사자 동의율 |
| 02 AI 보고서 품질 | 검사자 검토 결과 5단계 · 검토 소요시간 |
| **03 허용 한계 확인** | 두께 슬라이더 → KR 부록 2-7 허용치 즉시 조회 |
| **04 등급 판정 분포** | 실측 결함 5,405개를 규정 마진 축에 배치 |

`03`의 슬라이더가 `04`를 실시간으로 다시 계산하므로 두 패널을 붙여 둠.

### 탭 3 — 검사자·에스컬레이션

| 구획 | 내용 |
|---|---|
| 01 검사자 판정 눈금 | 검사자별 불합격 전환 마진 · 부위별 암묵지 후보 |

탭은 URL 해시로 기억되므로 `weldscan_dashboard.html#qual` 형태로 특정 탭을 바로 열 수 있음.

## 데이터

### 실측

| 출처 | 규모 | 용도 |
|---|---|---|
| 한국선급 강선규칙 제2편 적용지침 부록 2-7 7항 | 합격기준 5종 | 마진·등급 계산 |
| 동 규정 조문 벡터DB | 244청크 | 근거 조항 검색 |
| AI Hub 용접 AI 학습 데이터 (RT·일반강재) | 54,053장 | 결함 치수 실측 |
| 탐지 모델 평가 결과 | held-out 5,350장 | 검출률·오탐률 |

AI Hub RT·일반강재 라벨에서 추출한 결함 폴리곤은 총 99,202개이며, 대시보드는 10% 표본 5,405행을 사용함.

**결함 폴리곤 → 긴지름 → 마진** 경로가 실측으로 도는 유일한 구간임.

### 합성

판정 이력 3,674건 / 90일 / 검사자 13명.

공개 데이터에는 *"누가 언제 어떻게 판정했고 이견이 있었는지"*가 없음. 그런데 이 대시보드가 측정하려는 대상이 바로 그것이므로, 없으면 화면 자체가 성립하지 않음.

```
규정 일치율     88.4%  (불일치 428건 — 과잉 엄격 249 · 누락 179)
에스컬레이션    72.6%
판독 평균       243초 (4.1분)
모재두께        4.0 ~ 54.8 mm · 중앙 16.5
```

합성한 것은 **사람의 판정 확률 모델 하나**뿐임. 규정 계산은 난수 없이 규정표를 그대로 적용함.

### 클래스 비율 — 층화 표집

부위 6종 × 결함 5종 = 30칸 히트맵에서 **모든 칸이 통계적으로 읽히는 표본을 갖도록** 희소 클래스를 의도적으로 상향 표집함. 원분포를 그대로 쓰면 슬래그가 부위당 2~4건에 그쳐 칸 절반이 회색으로 비게 됨.

| 결함 | 합성 | AI Hub 원분포 |
|---|---|---|
| 정상 | 32.1% | 43.8% |
| 기공 | 46.1% | 45.0% |
| 슬래그 | 6.3% | 1.9% |
| 융합불량 | 9.1% | 5.4% |
| 균열 | 6.4% | 3.8% |

**실측 패널(탭2 `03`·`04`)은 이 상향의 영향을 받지 않음** — 그쪽은 AI Hub 라벨 원본을 그대로 씀.

생성 규칙은 `gen2.py` 345줄에 전부 공개되어 있고 시드가 고정되어 있어 재현 가능함.

### 계산 경로가 둘인 이유

| | 합성 이력 | 실측 치수 |
|---|---|---|
| 두께 | 건별로 보유 | **없음** |
| 마진 계산 시점 | 생성 시점에 미리 | 브라우저에서 실시간 |
| 슬라이더 반응 | 없음 | 있음 |

실측 라벨에는 모재두께가 없으므로 `03` 패널의 슬라이더 값을 5,405행 전체에 적용해 런타임에 계산함. 따라서 슬라이더를 움직이면 `03`과 `04`만 다시 그려짐. 정상 동작임.

`04 등급 판정 분포`가 **혼합**인 이유: 결함 치수·마진·등급은 실측이나, 공개 라벨에 사람 판정이 없어 *어느 마진에서 검사자가 갈리는지*만 탭3 `01` 패널의 산포(중앙 경계 1.06)로 겹침. 이 모델이 없으면 "불일치" 범례가 한 점도 찍히지 않음.

## 재생성

### 합성 판정 이력

```bash
python3 gen2.py
# → data2.json
```

같은 폴더의 `clauses.json`과 선급 규정표 `kr_appx2-7_rt_tables.json`이 필요함.
규정표를 다른 곳에 두었다면 `KR_TABLES=/경로/kr_appx2-7_rt_tables.json python3 gen2.py` 로 지정.

### 실측 치수 페이로드

```bash
# 라벨 JSON에서 (가중치 불필요)
python3 connect_yolo.py from-labels \
  --labels "02.라벨링데이터/TL_RTST_결함_2. 기공" ... \
  --out real_labels.json

# 학습 가중치로 추론 후 (best.pt 확보 시)
python3 connect_yolo.py detect \
  --artifacts ./porosity_yolov8seg --images ./films \
  --src weldscan_porosity/src --spacing 0.1 --thickness 20 \
  --out real_labels.json
```

산출된 JSON을 HTML의 `const REAL = {...}` 자리에 교체하면 됨.

`connect_yolo.py`는 검출기 출력에서 **긴지름**을 직접 계산함. 검출기 문서가 안내하는 등가지름을 그대로 사용하면 결함이 약 24% 작게 들어가 판정의 10.3%가 뒤집히므로, 이 경로를 우회하는 것이 이 모듈의 역할임. 등가지름 경로였을 때의 결과도 함께 계산해 `audit_equivalent_diameter.flipped`로 표시함.

## 알려진 한계

### 필름 배율(pixel_spacing) 복원 불가

규정은 밀리미터, 라벨은 픽셀 단위이나 두 단위를 잇는 값이 데이터셋에 없음. 구축활용가이드 확인 결과 원천데이터는 필름 스캔 후 **결함 부위를 임의 배율로 확대**해 생성되었으며 배율이 기록되지 않음. 원본 해상도가 682종으로 분산된 것이 그 결과임.

현재 0.10 mm/px를 가정값으로 사용하되 슬라이더로 노출해 민감도를 표시함. 현장 도입 시 RT 장비 사양에서 확보되며 확대 처리가 없으므로 이 한계는 소멸함.

### 등급 경계가 잠정값

합격선(마진 1.0)은 KR 규정 원문이므로 확정값이나, 1~4급 경계는 KS B 0845 원문 미확보로 선급 허용 한계의 1/2·2배로 잠정 설정함.

### 결함 윤곽 정확도

탐지 모델의 이미지 단위 성능(검출률 0.83 / 정확도 0.97)은 양호하나 결함 단위 마스크 품질(mAP50 0.363 / mAP50-95 0.118)은 낮음. 대시보드가 요구하는 것은 후자이므로, 현 수준에서는 *"기공이 있다"*는 신뢰 가능하되 *"그 기공이 6.2 mm다"*는 검증이 필요함.
