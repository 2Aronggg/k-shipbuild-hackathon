# 기공 유사사례 매칭 — 판단 메커니즘 상세

**대상**: 코드를 직접 안 봐도 "이 시스템이 왜 이렇게 판단했는지" 이해하고 싶은 팀원
**관련 파일**: `case_features.py`(특징 추출), `similarity.py`(유사도 계산·검색)

## 전체 흐름

```
신규 RT 이미지
    ↓ ① YOLO 검출
기공 인스턴스들 (좌표, 크기, 개수)
    ↓ ② 특징 추출 → "형태 / 분포 / 크기" 프로필로 요약
    ↓ ③ 유사도 계산 → 26,299건 과거 사례와 비교
    ↓ ④ 다양성 선택(MMR) → 겹치지 않는 top-5 고르기
    ↓ ⑤ 보고서 생성 → "위험도 + 왜 비슷한지" 자연어 요약
```

## ① → ② 특징 추출: 형태 / 분포 / 크기

### 형태 (원형/구형 vs 길쭉한)
기공 폴리곤 좌표의 퍼진 방향(장축/단축 비율, elongation)을 계산해서:
- **elongation ≥ 1.8배** → "길쭉한 기공"
- 그 미만 → "원형/구형"

### 분포 (단독 / 군집 / 산재 / 선상)
기공이 여러 개일 때, 중심좌표들의 공간 배치로 판단:

| 분류 | 조건 |
|---|---|
| 단독 | 기공 1개 |
| 군집 | 기공들 간 최대 거리가 이미지 대각선의 5% 이하 (모든 방향으로 다 가까움) |
| 선상 | 기공 **8개 이상**이고, PCA 분석상 한 방향으로 90% 이상 정렬됨 |
| 산재 | 위 조건에 안 걸리는 나머지 (넓게 퍼짐) |

> **왜 선상은 8개 이상만 인정하나?**
> 기공이 3~4개뿐이면, 완전히 무작위로 흩어진 경우에도 통계적으로 "일렬처럼" 보일 확률이 58.8%나 됐다(직접 시뮬레이션으로 확인). 실제로 처음엔 이 오탐 때문에 전체 기공 사례의 43%가 "선상"으로 잘못 찍혔었다. 최소 개수를 8개로 올리자 오탐 3%, 진짜 선상 탐지율 99%로 정상화됐다.

### 크기 (소/중/대)
등가직경(mm)을 **전체 데이터 분포의 33/67 백분위**로 3등분. 절대 mm 기준이 아니라 "이 데이터셋 안에서 상대적으로 작은/중간/큰 편"이라는 뜻.

> ⚠️ 픽셀→mm 환산 계수가 아직 임시값(0.1)이라, 실제 mm 절댓값은 나중에 조정될 수 있음. 소/중/대 **상대적 순위**는 이 계수와 무관하게 정확함.

## ③ 유사도 계산: 2단계 가중치 구조

### 1단계 — 큰 틀(coarse), 전체 점수의 88%

팀이 정한 별점(★)을 그대로 가중치로 사용:

| 축 | 가중치 | 계산 방식 |
|---|---|---|
| **분포** | ★★★ (3) | 카테고리 일치 60% + 실제 퍼진 범위(연속값) 40% 혼합 |
| **형태** | ★★ (2) | 길쭉한 기공 비율 차이 |
| **크기** | ★ (1) | 소/중/대 분포 차이 |

> **왜 분포에 "연속값 40%"를 섞었나?**
> 처음엔 "같은 카테고리면 무조건 1.0"으로만 판단했더니, 24,000건이 넘는 DB에서 서로 다른 사례들이 전부 만점(1.000)으로 묶여버렸다. "산재"라는 카테고리는 같아도 실제로 얼마나 넓게 퍼졌는지는 다를 수 있어서, 그 실제 퍼진 정도(extent)를 카테고리 판정과 함께 섞어 점수가 자연스럽게 갈라지도록 고쳤다.

### 2단계 — 미세 조정(fine tiebreak), 전체 점수의 12%

같은 큰 틀(coarse) 점수를 가진 사례들 사이에서, 아래 4가지 연속값을 **똑같은 비중(각 25%)**으로 섞어 순위를 세밀하게 갈라준다:

| 요소 | 의미 |
|---|---|
| 기공 개수 차이 | 몇 개나 있는지 |
| 평균 등가직경 차이 | 실제 크기 mm값 (소/중/대로 뭉개지기 전 원본) |
| 퍼진 범위(extent) 차이 | 가장 멀리 떨어진 두 기공 사이 거리 |
| **최근접 거리(mean_nn_norm) 차이** | 기공들이 서로 얼마나 가까이 뭉쳐있는지 |

> **최근접 거리가 왜 따로 필요한가?**
> "퍼진 범위(extent)"만으로는 "기공 4개가 한쪽에 3개 뭉치고 1개만 멀리 떨어진 경우"와 "기공 4개가 전체적으로 고르게 흩어진 경우"를 구분 못 한다. 둘 다 가장 먼 두 점 사이 거리는 비슷할 수 있기 때문. 그래서 "각 기공이 제일 가까운 이웃과 얼마나 떨어져 있는지"를 추가로 봐서, 몇 개씩 뭉쳐있는 패턴("기공 2~3개가 뭉쳐있다" 같은)을 구분해준다.

### 최종 점수 계산식

```
최종 점수 = 큰 틀(coarse) × 0.88 + 미세조정(fine) × 0.12
```

## ④ 다양성 선택 (MMR)

큰 틀 + 미세조정까지 다 반영해도, 26,000건이 넘는 DB에는 신규 사진과 **거의 완전히 동일한 사례가 여러 건 존재**할 수 있다(실측 확인됨). 이걸 그대로 top-5로 보여주면 "거의 똑같은 복제품 5개"가 나열되는 문제가 생긴다.

그래서 **어떤 걸 보여줄지 고르는 방식**을 다음과 같이 바꿨다:
- **1등은 무조건 진짜 최고 매치**
- **2등부터는** "신규 사진과 충분히 비슷하면서(관련성 50%) + 이미 뽑힌 것들과는 겹치지 않는(다양성 50%)" 사례를 우선 선택

이 과정에서 점수 자체는 절대 조작하지 않는다 — 화면에 보여줄 5건을 **고르는 순서**만 바뀐다.

## ⑤ 판정 근거 (위험도)

각 유사사례의 "실제 판정"은 **AI Hub 원본 라벨(annotation_case)을 그대로 신뢰**한 것이다:
- 기공 라벨이 있는 이미지 → "이상(abnormal)"
- 정상 라벨 이미지 → "정상(normal)"

위험도는 top-5 중 "이상" 비율로 계산:
- 60% 이상 → 높음
- 30~60% → 보통
- 30% 미만 → 낮음

> **KS B 0845 합격/불합격 등급 판정은 이 시스템의 역할이 아님** — 그건 룰엔진(필호 파트)이 담당. 여기서 말하는 "위험도"는 등급 판정이 아니라 순수하게 "과거에 비슷한 패턴 중 결함이 있었던 비율"이다.
