입력: `2편_2026.pdf` (361쪽, 한국선급 배포본, 규칙 + 적용지침 합본)

## 2. 처리 과정

```
2편_2026.pdf
  │ PyMuPDF get_text()            361쪽 → 페이지별 텍스트
  ▼
clean_page()                       머리글 8종 제거 (상단 8줄 안에서만), 줄바꿈 복원
  │                                · "2 편재료및용접", "2 장용접", "선급및강선규칙적용지침2026", 쪽번호
  │                                · 단어 중간에서 잘린 줄은 붙이고(된⏎다 → 된다), 문장 끝(.)이면 공백,
  │                                  (1)/(가)/N./표/그림 으로 시작하면 새 줄
  ▼
parse_structure()                  편>장>절>조(NNN.) 트리, 머리글에 "적용지침"이 보이면 doc_type=guidance,
  │                                "부록 2-N 제목" 이후는 chapter="부록 2-N", 항목 "1. 적용"이 article
  ▼
필터                               chapters = ["2", "부록 2-7", "부록 2-12"]  (1장 재료·다른 부록 제외)
  ▼
split_paragraphs()                 조 본문을 항(1.)으로 나누고, 700토큰 넘는 덩어리는
  │                                (1) → (가) → (a) → 문장 순으로 더 잘게
  ▼
make_chunks()                      항 단위 그리디 패킹(≤700토큰), 직전 항 1개 오버랩(150토큰 이하일 때만),
  │                                breadcrumb 접두, 토픽 태그, 인용문자열, 페이지 범위
  ▼
tables_json                        표 12~16 수동 전사 JSON → 표당 청크 1개 추가 (text + table_json)
  ▼
build_indexes()                    chunks.jsonl / BM25Plus(문자 2·3-gram) / [bge-m3 → FAISS] / manifest
```

### 파서를 실제 PDF에 맞추면서 고친 것

| 문제 | 증상 | 수정 |
|---|---|---|
| 머리글이 공백 없이 추출됨 | `2 편재료및용접`, `부록2-7 선체용접이음부의비파괴검사기준` | 정규식을 무공백 형태로, 상단 8줄 안에서만 적용 |
| PDF 줄바꿈이 단어 중간 | `안 된⏎다` → 공백으로 이으면 `된 다` | 문장부호로 끝나지 않으면 붙여 쓰기 |
| 조 제목 줄에 본문이 붙음 | `103. 특수용접이 장에 규정하지…` | 제목 패턴 줄에는 다음 줄을 붙이지 않음. `312. 제목 (2021) 본문…`처럼 한 물리행이면 연도 뒤에서 분리 |
| 적용지침이 같은 PDF 뒷부분 | 규칙 309와 지침 309가 같은 번호 | 페이지 머리글로 doc_type 전환, doc_id·citation에 "지침" 구분 |
| 부록은 NNN. 조 번호가 아님 | `1. 적용`, `7. 합격기준` | 부록 모드에서는 짧은 `N. 제목` 줄을 조로 인식 (문장으로 끝나는 `N. …다.`는 제외) |
| 조 하나가 수천 토큰 | 404조 3,900토큰 | 항 → 호 → 목 → 문장 순 계층 분할 |
| 거대 항 오버랩 시 청크 중복 | 합격기준 split 0·1이 거의 동일 | 150토큰 넘는 항은 오버랩에서 제외 |
| 표가 한 줄로 뭉개짐 | `점 수1236101525` | 판정에 쓰이는 표 12~16은 페이지 이미지를 보고 JSON으로 수동 전사 |

## 4. 검증 방법 (verify.py)

```bash
python verify.py out raw/2편_2026.pdf
```

출력 순서: 청크 통계 → 문서·장별 개수 → 토픽 분포 → 조항 목록(제목·청크 수) → 무작위 5개 청크 본문과 원본 페이지 대조(True/False) → 검색 스모크 5건.

직접 검증하실 때 보실 것:
1. 조항 목록에서 규칙 2장 101~609가 빠짐없이 있는가 (있음)
2. 무작위 청크의 `page_start`로 PDF를 열어 내용이 그 페이지에 있는가
3. `tables/kr_appx2-7_rt_tables.json`의 숫자를 PDF 326~327쪽 표와 대조 (수동 전사라 오타 가능성이 가장 큰 곳)

## 5. 남은 것

**dense.faiss(bge-m3 임베딩)** — 이 환경은 HuggingFace 접근이 막혀 있어 모델을 받지 못했습니다. 팀 PC에서 아래 한 줄이면 됩니다. 나머지 파일은 그대로 재사용됩니다.

```bash
pip install sentence-transformers faiss-cpu
python build_vector_db.py --src sources.yaml --out out     # --dry-run 제거
```

지금은 BM25만 동작해서 "균열은 허용되는가" 같은 자연어 질의가 엉뚱한 조를 잡습니다(스모크 결과 참고). 조항 번호·용어 검색은 이미 정확합니다. 임베딩을 붙이면 자연어 쪽이 해결됩니다.

**KS B 0845 (2021)** — 구매 후 `raw/KS_B_0845_2021.pdf`로 두고 `sources.yaml`에서 `skip: false`. 표는 부록 2-7과 같은 방식으로 수동 전사 권장.

**룰엔진 수정** — `regulations.py`의 `basis`를 이 DB의 `citation` 형식으로 맞추고, 기공 문턱값을 표 14·15 기준(긴지름 → 점수, 시험시야 내 합산, 모재두께별 상한)으로 다시 짜야 합니다. 현재 노트의 "직경 1.5 / 3 mm → 1~3급"은 KR 표와 맞지 않습니다.
